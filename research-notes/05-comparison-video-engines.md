# 05 · Remotion / HyperFrames / web-video-presentation 三方对比

> 来源：Remotion 官方文档（remotion.dev，一手）；**HyperFrames 本地实装全量实读**（`~/.claude/plugins/cache/claude-plugins-official/hyperframes/0.8.4/skills/` 下 18 个 skill，一手，含 remotion-to-hyperframes 移植 skill 与 PR #214 interop 文档）；web-video-presentation 见 [01-skill-anatomy.md](01-skill-anatomy.md)。

## 1. 坐标系：三种时间模型

三者回答同一个问题——"**怎么用代码做视频**"——但选了三种不同的时间模型：

| | **Remotion** | **HyperFrames** | **web-video-presentation** |
|---|---|---|---|
| **时间模型** | **帧函数**（frame） | **seek 函数**（time → pixels） | **step 函数**（反时间轴） |
| 本源 | React 库 | HTML + GSAP + CLI 工具链 | Vite 模板 + 方法论文档 |
| 作者 | Remotion（独立公司，2021~） | **HeyGen**（业务 = AI 视频生成） | ConardLi garden-skills 沉淀 |
| 产物 | React 代码 | 单个 HTML 合成文件 | React 项目 + 录屏成片 |
| 成片方式 | 无头渲染（程序化） | 无头渲染（程序化） | **人肉录屏**（Auto 模式） |
| 输出确定性 | 确定性（帧函数） | 确定性（seek 函数） | 非确定性（真时间轴上跑） |
| 音画同步 | 代码声明（`<Audio>` 序列） | data 属性声明 + 框架接管媒体播放 | 运行时 `audio.ended` 事件驱动 |
| 时序的形态 | 命令式（代码里 useCurrentFrame 推导） | **声明式（data-* 属性）** | 数据化（narrations.ts） |
| 面向谁 | React 开发者 | **Agent 一等公民** + HTML 作者 | 口播创作者 |

## 2. Remotion：视频是帧的函数

- 官方理念（the-fundamentals）："give you a frame number and a blank canvas"；视频 = 帧的函数；`useCurrentFrame()` 让组件成为当前帧号的纯函数
- 渲染管线：Chrome Headless Shell 逐帧截图 → `stitchFramesToVideo`（"Takes a series of images and audio information generated by renderFrames() and encodes it to a video"）→ ffmpeg 编码；`ffmpegOverride` 钩子可改底层 ffmpeg 命令；`npx remotion render` 出 mp4、`--sequence` 出帧序列
- `delayRender`/`continueRender`：阻塞渲染直到异步资源（字体/图片）就绪，默认 30s 超时
- Composition = 组件 + 元数据（width/height/durationInFrames/fps），帧 0-indexed
- **强项**：React 生态全能力（state/组件/MUI 都行）、`interpolate`/`spring` 精确插值、Lambda 云渲染
- **代价**：必须学 React + 专用 API；时间轴思维——每个动画都要指定帧号/时长；Agent 无法"看到"渲染结果就预判 2.3s 该发生什么

## 3. HyperFrames：视频是 seek 的函数（Agent 一等公民）

### 3.1 核心设计决策（determinism-rules.md 原文）

> "The renderer takes a time value and produces a pixel buffer. There is no notion of 'playback' — every frame is a fresh seek."

- **声明式时序在 DOM**：`data-start` / `data-duration` / `data-track-index` / `data-composition-id` 直接写在 HTML 属性——**时序是可静态审计的文本**，`npx hyperframes check` 用一个浏览器 session 审计 lint / runtime / layout / 对比度，persistent findings gate exit code
- **动画收敛单一运行时**：每个合成一个同步构建的 `gsap.timeline({ paused: true })`，注册在 `window.__timelines["<id>"]`，渲染器按时间 seek。非 GSAP 运行时（CSS/WAAPI/Lottie）由运行时推断时长，Three.js 不可推断必须手写 `data-duration`
- **确定性黑名单**（与 web-video-presentation 的"禁 setTimeout"同一张表，但更严）：`Date.now()` / `performance.now()` / 未种子化 `Math.random()` / 渲染期网络 / hover-scroll-pointer 状态 / `repeat: -1`（要有限循环，`floor` 不许 `ceil`）；动画只许 allowlist 属性（opacity/x/y/scale/rotation/色彩/transform），禁 tween `display`/`visibility`
- **比 Remotion 激进**：`useState` / `useReducer` / 带依赖的 `useEffect` / React UI 库（MUI/Chakra/antd…）驱动动画 = lint **blocker**，直接拒绝翻译——因为 React state 不可 seek。**确定性优先级高于表达能力**（与 Remotion 的哲学分野）
- 真有这类 Remotion 项目 → PR #214 runtime interop：esbuild 打包 Remotion `<Player>` 挂进 HF 合成、暂停、注册 `window.__hfRemotion`，由 HF 渲染循环逐帧 `seekTo(frame)`

### 3.2 工程化（hyperframes-cli）

```
init → catalog（"Find the move"：搜现成动画 primitive，add 安装，没有才手写）
→ lint（快速迭代）→ check（终门禁：lint + runtime + layout + motion 断言 + WCAG 对比度）
→ snapshot（指定时刻截帧）→ preview --background（Studio 时间线预览）
→ render（draft/high/docker/batch/cloud/lambda/cloudrun）
```

- **`--batch rows.json` 变量化批量出片**——HeyGen 业务本质 = 一个模板出千条视频
- `remotion-to-hyperframes` 移植 skill：lint_source.py（blocker/warning/info 三级）→ api-map 翻译（Composition→data-*、useCurrentFrame→GSAP tween）→ **SSIM 评估器**（渲染两版对比，阈值按复杂度分层 ~0.02；还要求两边像素格式一致否则测的是编码差异）——"a translation that looks right but renders 0.05 SSIM lower is silently wrong"
- 工作流路由：slideshow / embedded-captions / talking-head-recut / music-to-video / motion-graphics / pr-to-video / product-launch-video / **faceless-explainer** / general-video——每个是独立 skill，入口 `/hyperframes` 意图面谈 → 写 `BRIEF.md` 作为唯一路由产物
- **faceless-explainer = "text → video"**：brief → 设计预设（frame-presets + build-frame.mjs 确定性 remix 品牌色）→ STORYBOARD.md（帧计划：每帧 duration/transition/voiceover/narrative）→ SCRIPT.md（锁稿）→ 音频 → **逐帧 subagent 并行**（frame-worker 契约）→ index.html 组装 → render。与 web-video-presentation 的 article → script → outline → 章节同构，但**直接产出可渲染视频，没有录屏环节**

### 3.3 与 web-video-presentation 的镜像关系

| 维度 | HyperFrames | web-video-presentation |
|---|---|---|
| 时序数据化 | data-* 属性 → linter 静态审计 | narrations.ts → extract-narrations |
| 子任务并行 | 逐帧 subagent + frame-worker 契约 | 模式 C 并行章节 + 独立 CSS 前缀 |
| 计划层 | STORYBOARD.md（帧 = key moments） | outline.md（step = 口播节拍） |
| 质量门禁 | `check` exit code gate | 自检协议（agent 纪律，未自动化） |
| 成片 | 程序化渲染 | 人肉录屏 |

## 4. 联系：同一条演进线

```
Remotion (2021)              HyperFrames (HeyGen)                    web-video-presentation
"React 组件即视频"      →    "HTML + data 属性即视频，Agent 可 lint"  →   "口播节拍即视频，浏览器即播放器"
帧函数 · 程序化渲染           seek 函数 · 程序化渲染                   step 函数 · 人工录屏
时间轴逐步……从命令式代码 → 声明式数据 → 彻底消失（离散化）
```

- HF 的 data-* 与 wvp 的 narrations.ts 干同一件事：**把时间结构从命令式代码里拉出来变成可静态审计的数据**（前者给 linter，后者给 extract 脚本）
- HF 逐帧 subagent ≈ wvp 模式 C（同样的"物理隔离 + token 兜底"策略）
- HF 专门写"从 Remotion 逃出来"的 skill + SSIM 评估器——说明确定性 seek 模型被视为足够不同、值得写迁移工具的范式
- 三者共同的深层原则：**确定性**（禁时钟/随机/hover）——wvp 的"禁 setTimeout、章节是 step 的纯函数"是同一哲学的低配版；HF 把它推到极致（连 React state 都不许），wvp 用"人肉录屏"绕开了逐帧确定性的需求

## 5. 启发 → 行动项（对复刻/改进 web-video-presentation）

1. **确定性改造是 render 的前提**。MaskReveal 实证问题（transition 挂载即终态）在 HF 的 seek 模型下不可能存在。最小修法：入场统一 keyframes；完全体：GSAP paused timeline + `tl.seek(t)`（动画变成时间的纯函数，"截第 N 帧"才有意义）
2. **`npm run render` 两个参照实现**：最简版 = 每 step 等 `getAnimations()` finished → 截终态帧 → ffmpeg concat（duration = 音频实测时长）→ `-fps_mode cfr`；完全体学 Remotion 两阶段（renderFrames → stitch）保 CFR。坑位清单见 [04-improvements.md](04-improvements.md) 第二节
3. **学 HF 把时序再数据化一层**：章节内 sub-beat（"数字先滚、横条后长"）现在埋在 CSS 里；HF 证明声明式化后 check 才能自动审计。可在章节目录加可选 `beats.json`（sub-beat 级时长声明）
4. **学 HF 的 check 门禁形态**：`npm run check` 加无头 seek pass（Playwright 逐 step 收集 console error / 布局溢出 / getAnimations 异常），**persistent findings gate exit code**——自检从纪律变 CI
5. **差异化守住**：不全盘程序化。wvp 的真正优势 = 浏览器即成片预览 + 录屏保真人感 + 零渲染依赖的轻盈。终态 = 双出口：录屏（真人感）+ render（确定性/批量/CI），而不是被 HF 带向全自动
6. **顺手的情报**：HF 的 `catalog`（"find the move"——搜现成动画 primitive 再手写）值得抄进 wvp：做一个"章节动画词汇表"索引（reveal / count-up / path-draw / split-compare…），chapter agent 先查表再自由设计——压缩重复发明，也天然是反"整章一种动画"的机制

## 6. 选型建议（什么场景用什么）

| 场景 | 推荐 |
|---|---|
| React 团队、需要精确插值/组件生态、云渲染 | Remotion |
| Agent 驱动、要静态可审计时序、批量变体出片、声明式偏好 | HyperFrames |
| 口播/文章驱动、要浏览器实时预览、真人录屏感、极低依赖 | web-video-presentation |
| 口播驱动 + 要程序化成片 + 要批量 | **wvp 引擎 + 补 render 出口**（本研究的核心建议） |
