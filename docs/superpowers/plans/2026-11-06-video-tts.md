# video-tts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `plugins/video-toolkit/skills/video-tts` — a Claude Code skill that turns a Chinese SRT + video into a time-fitted Chinese dub and a finished mp4, using either local MLX Qwen3-TTS or the online Bailian `qwen-audio-3.1-tts-plus` / `qwen3-tts-flash` via `bl`.

**Architecture:** A provider abstraction (`local_mlx` / `online_bailian`) feeds a single pipeline: parse SRT → synthesize each cue (cached) → trim/validate → fit to its time window with ffmpeg atempo → place into one full-length 24 kHz track → mux with the video. The CLI is non-interactive; `SKILL.md` instructs Claude to collect every choice with `AskUserQuestion` before calling it.

**Tech Stack:** Python 3.10+, numpy, soundfile, ffmpeg/ffprobe, mlx-audio (local only), `bl` CLI (online), pytest.

**Spec:** `docs/superpowers/specs/2026-11-06-video-tts-design.md`

## Global Constraints

- Output audio is **24 kHz mono**; master track length equals video duration (or last cue end when no video).
- Fit thresholds: warning speed **1.15**, hard max **1.30** (`--max-speed` overrides the hard max). Never slow audio down; only speed up, then pad silence.
- Never overlap the next cue; never use `-shortest` when muxing.
- SRT text is already Chinese; no ASR/translation/multi-role.
- Local provider is macOS Apple Silicon only; online provider works anywhere `bl` does.
- Online auth reuses `bl auth status`; the skill must never receive, store, or print an API key.
- All user choices in `SKILL.md` use `AskUserQuestion` (max 4 options/question; header ≤12 chars; `multiSelect` required).
- Online voice catalog is fixed: 4 flagship `*_v3.1` voices → `qwen-audio-3.1-tts-plus`; 10 curated Qwen-TTS voices → `qwen3-tts-flash`. Never mix voice/model.
- Cache key covers provider + model + voice + instruct + lang + text; invalid audio is never cached.
- Tests must not load a real TTS model or call the network by default.

## Review Focus

1. **SRT cues with zero/negative/overlapping times** — must error or clamp with a clear cue index, never crash on a negative buffer index or silently drop a line. Pinned in Task 1 tests.
2. **Empty/all-silent/NaN synthesis output** — must fail the run (or be marked failed under `--continue-on-error`), never be cached or muxed. Pinned in Task 8 tests.
3. **Cue that still does not fit after 1.15×** — must spill into the inter-cue gap, then compress up to max, then truncate at `next_start`; it must never run into the next cue. Pinned in Task 2 and Task 9 tests.
4. **`bl` missing / not authenticated / 401** — must surface the login link or offer local fallback, never fail silently or fake success. Pinned in Task 5 tests.
5. **Video codec incompatible with mp4, or missing audio stream after mux** — must re-encode H.264 or delete the partial output and error. Pinned in Task 10 tests.

- [ ] **Step 3: Implement `audio_fit.py`**

`plan_fit` branch order:
1. `available <= 0` → `NO_WINDOW`, speed 1.0.
2. `synth_duration <= slot` → `FIT`, speed 1.0.
3. `cap = min(warn_speed, max_speed)`; if `synth_duration / slot <= cap` → `FIT_COMPRESS`, speed `synth_duration / slot`.
4. if `synth_duration / cap <= available` → `SPILL`, speed `cap`, warning `"spills past subtitle end but stays before next cue"`.
5. `needed = synth_duration / available`; if `needed <= max_speed` → `COMPRESS_MAX`, speed `needed`, warning.
6. else `TRUNCATED`, speed `max_speed`, warning `"truncated at next cue start"`.

`trim_silence`: compute RMS over `window_ms` windows; find first/last window above `threshold`; slice with one window margin; apply 10 ms linear fade-in/out; raise `ValueError` if none.

`apply_atempo`: return input when `speed == 1.0`; write temp WAV with `soundfile`, run `ffmpeg -y -i in.wav -filter:a atempo=<speed> out.wav`, read back; chain factors >2.0 as `atempo=2.0,atempo=...`.

`split_long_text`: split after `。！？!?；;`; accumulate sentences up to `max_chars`; also split a single sentence longer than `max_chars` at `max_chars` boundaries; never return an empty chunk.
