01

SKILL.md 框架骨架

六个章节立下全部运行契约
front
frontmatter 定位声明

校对 / 翻译 / 精简 SRT、MD、TXT；结构由脚本保护；需要用户选择必须 AskUserQuestion；翻译必须独立 agent 审校信达雅；不自动翻译、不摘要、不启动配音

§1
用户选择必须使用 AskUserQuestion

任务类型 / 目标语言 / 时间轴策略 / 覆盖文件——一律控件收集，不得文字列选项、不得默选、不得把推荐值当已选择；控件不可用时暂停并说明缺失能力

§2
先理解完整句意，再组织目标字幕

翻译与审校 agent 都必须先完整读 line-break-cases.md；ASR 条目是时间容器不是独立句子；中文默认单行；全篇统一术语与指代；ASR 疑点入审校记录不进成品

§3
时间轴与输出

翻译推荐 semantic（语义段重排，条数可变）；校对默认 preserve（1:1 保留时间轴）；输出 {原名}_refined 自动编号，永不覆盖源文件

§4
执行方式

prepare 一个命令取全部材料；能容纳输入输出时一次处理，不按 40/60/200 条机械切块；确实超容量才按句意分批积累为一份 draft——这一条正是 v2 推翻的假设

§5
翻译必须经过独立 agent 审校

实际调用另一个独立 agent，不灌翻译者结论；未具备独立 agent 能力时明示"审校未完成"，不得把草稿当最终译文交付

§6
只交付用户需要的文件

素材目录只新增最终文件；分块 / JSON / 审校报告全留系统临时目录，成功即清理，失败可续用；不生成 _refine_work

02

三命令协议

薄文件层 · 中间材料不进素材目录
prepare 输入 --task translate --target-lang zh [--timing semantic --timing-reason srt-estimate]

准备全文

解析输入 → 系统临时目录建唯一任务（request.json 内嵌原文快照与哈希）→ 返回全文材料、每条时长、术语内容、draft_path 与 review_path；源文件旁不建任何工作文件夹

review-input workdir --draft draft.json

独立审校材料

审校 agent 一个命令拿到：完整原文、最终带时间轴候选、语义段与内部锚点、阅读诊断、术语、四项版本摘要——无需通读 skill 实现或重复准备步骤

finish workdir --draft draft.json --review review.json

验证一次输出

核对审校记录、覆盖与版本 → 原子发布 → 清理临时任务；翻译必须提供 --review，仅结构通过不能交付；失败保留临时目录供重试

退出码 0 成功退出码 2 用法错误退出码 3 输入 / 结构 / 审校 / 文件失败 临时目录 mkdtemp 唯一 · 成功清理 / 失败保留
03

三种时间模式与稿件格式

模式决定 draft 结构与校验规则
preserve · 校对默认 / 兼容

严格保留原时间轴

原条目数、序号、时间轴完全不变，只替换正文；样式标签集合必须一致；渲染后回读逐条比对

"items": [{"id": "entry-000001", "text": "译文"}]
semantic · 翻译推荐

自然重新分段

按完整句形成语义段，段内按意群重排，条数可变；模型用连续原文片段标对应，程序核对全文覆盖并算毫秒——时间不手填

"blocks": [{"id": "b001", "units": [ {"source": "Even big AI companies", "text": "连大型 AI 公司也开始"}]}]
resegment · 旧稿兼容

手填时间重分段

仅兼容已有显式稿件，不作翻译推荐路线；每条引用连续有序源条目，时间须落在对应源范围内，覆盖全文且首尾保留

"items": [{"source_ids": ["entry-000001"], "start": "00:00:00,000", "end": "00:00:06,000", "text": "按中文意群组织的字幕。"}]
MD：editable=false 块只读原样回填MD 保护：链接目标 / 行内代码 / 结构标记 不可变SRT：样式标签 集合不变TXT：不得引入 Markdown 标记
04

确定性守护机制

脚本管结构与文件，语义归宿主模型

解析容错矩阵（诊断 ≠ 阻塞）

  • 只诊断不掩盖：序号缺失 / 重号 / 断续 · 既有时间重叠 · 空正文 · 零时长——既成事实照单记录
  • 容错：序号行可选 · 时间轴整行保留（含 X1: 坐标附加）· CRLF / CR / LF 统一 · UTF-8 BOM 剥离
  • 阻塞：时间无法解析 · 终止早于起始——此类文件不产出成品

结构逐字保留

  • 条目 ID 按源位置生成 entry-%06d，两个都显示 "5" 的条目依然是两个不同源条目（重号免疫）
  • 渲染只替换正文：序号行与时间轴行逐字保留；new_texts 出现未知 ID 即报错，映射错位必须暴露

四哈希绑定

source_sha256draft_sha256candidate_sha256request_sha256
  • request 含 engine_sha256（四个 .py 文件字节摘要）——改代码、改排时参数同样使旧审校失效
  • 审校报告四哈希与命令实际值逐一核对，不能手算或手换哈希冒充复核

原子发布

  • 临时文件写入 + fsync → 硬链接 落盘，不存在 exists→replace 覆盖竞态
  • 已有文件自动编号 _refined_2；源文件永不被覆盖；用户经控件明确选择后才 --overwrite
  • Windows 文件系统需支持硬链接，不支持则明确失败、不降级
05

语义排时引擎

semantic_timing.py · 确定性插值
规范化全文剥样式标签 · 合并空白 · 条目间单空格连接
→
字符范围每条目记 [start_char, end_char) 与句级时间
→
source 回显匹配意群 source 必须连续覆盖全文，不切单词
→
时间插值句级线性插值；词级则必须落在词边界
→
留白检测≥800ms 间隔为段界，意群 / 语义段不得跨越
→
尾延 ≤300ms只借段内短空隙，不挪下条入点、不跨停顿
→
诊断渲染CPS / 行长 / 闪现报告 → 渲染 → 回读验证

词级时间戳 schema（更细依据）

  • words: [{text, start_char, end_char, start_ms, end_ms}] 逐词校验：字符切片与全文完全一致、时序不重叠、落在对应句级范围内
  • pauses 停顿区间不得与任何词时间重叠；只有真实数据才能选 word-timestamps，audio-align 声明被拒绝
  • 1~2ms 舍入重叠归一化为共同边界；超过容差的重叠阻塞自然重排

集中参数 DEFAULTS（可 --timing-parameters 覆盖）

段目标 20s / 段警示 30s段界留白 800ms 舒适 5 字/s警戒 7 字/s行长 18 字 短条 800ms长条 6s尾延 300ms重叠容差 2ms
  • 阅读诊断（汉字压力 / 短闪 / 长条 / 超两行 / 行长）为提示不阻塞——先改表达，不为消警告删事实
06

质量标准与独立审校

翻译与审校共用同一套标准
中文默认单行，不在条内换行行长舒适区 14~18 字 阅读目标 3~5 字/s · 警戒 7 字/s意群断句，不拆主谓动宾 保真优先：不删否定 / 条件 / 数字术语 · 作品名 · 产品名全篇统一
review.json · 审校结构化结论 
{
  "reviewer_id": "独立 agent 标识（≠译者）",
  "source_sha256": "命令返回，不手算",  … 四哈希
  "criteria": ["信", "达", "雅"],
  "coverage": [[1, 163]],
  "verdict": "pass",
  "findings": [{"source_ids": […], "dimension": "信",
    "severity": "required", "status": "resolved", …}]
}

信达雅三维（现代翻译实践定义）

  • 信 意义不背离：事实、否定、条件、因果、程度、先后、数字、指代、专名、语气
  • 达 通顺流畅：完整意群、自然断句、跨条衔接、实际阅读负担——准确却难懂仍需修订
  • 雅 得体（Register & Tone）：契合题材、角色、身份、情绪——不以古雅华丽为目标
  • coverage 须顺序覆盖全文无遗漏；必修未 resolved 不得 finish；两轮修订后仍有必修即不通过
  • 每条 finding 写明位置 / 维度 / 理由 / 建议，不能只写分数或"有翻译腔"
