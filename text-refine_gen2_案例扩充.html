回归用例 E1~E4

"纯 prompt skill 没有可跑的单测"——所以用例先成文
#验证点输入（条目正文 / 时长）必须满足
E1意群断句"We found traces of explosive materials inside the warehouse." / 2.6s双行各自成意群；"的"不悬行尾；总字数 ≤ 硬上限（时长×7≈18）
E2连词归属"I didn't tell you the truth because I thought you couldn't handle it." / 2.2s因果引导词不在第一行行尾领空；总字数 ≤ 硬上限 15
E3减词"Well, to be completely honest with you, I actually really don't remember…" / 2.0s删 well/actually/really 填充词；≤14 字；信息点一个不缺
E4动作化拆解"The failure of the cooling system caused the core temperature to rise…" / 2.3s无名词化直译；拆成两个动作短句；保住危机语气
共同断言（所有用例）：时间轴与序号原样保留 · 输出仍是 UTF-8 无 BOM 的 SRT · 无 Markdown 标记 彩蛋：E1~E4 就是今日 line-break-cases.md 里"仓库炸药 / 因果引导词 / 口供填充词 / 冷却系统"四个正反例的原型 "硬上限 = 时长×7"——②代已在用 prompt 语言实现 CPS 警戒线，周日它变成 max_han_cps=7

生态咬合（1889969）

一行改动，三个 skill 的时间预算契约对齐
1889969 · SKILL.md 唯一的一行改动 · 与其他 skill 配合
- 交给 video-tts 配音时，每秒 3~5 字的阅读速度预算正好也是配音语速预算，译文长度天然匹配口型时长。
+ 交给 video-tts 配音时，时间对齐由它的语义合并（--merge-plan，读全文按语义分组）兜住——
+ 按语义段合并成块后整段朗读，配音语速预算约 4 字/秒（另计标点停顿），比字幕阅读预算宽松，
+ refine 不必为配音额外减词。

add-subtitle 契约

  • 每条 ≤ 12 字——确定要叠加字幕时，翻译阶段就按 12 字拆条

video-tts 契约

  • --merge-plan 语义合并读全文分组，配音预算约 4 字/秒（另计标点停顿）

text-refine 的自由度

  • 阅读预算（3~5 字/秒）严于配音预算 → refine 不必为配音额外减词，两个预算解耦
同一次提交里 audio-transcribe 引入词级时间戳修正转录偏移——⑤代 word-timestamps schema 的生态源头
