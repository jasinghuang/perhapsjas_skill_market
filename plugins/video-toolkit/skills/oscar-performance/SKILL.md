# oscar-performance

把“AI 演员不会演”的剧本或提示词，整理成有任务、有触发、有过程、有对手反馈、能接续的表演指令，并编译成可复制的视频提示词。

## 适用与边界

- 输入：剧本、对白、故事大纲、分镜文字、已有视频提示词。
- 输出：默认全量版——理解卡、导演阐述、场景引擎判断、表演节拍表、八维检查、镜头/声音摘要、风险表、最终提示词、未解决冲突。
- 三种模式：创作（从剧本写）、修订（保留原稿结构，只改表演与直接耦合冲突）、诊断（AUDIT，不重写，只给最弱一环与修复）。
- 不调用视频生成、不索要图片/音频/视频、不把文字设计说成成片效果。

## 核心原则

0. **本 skill 的八维、五元素、acting task 定义是权威口径。** 不要用通用表演教材或“自然一点”之类的建议替换它们。
1. **先理解，再设计；先空间，再镜头；先因果，再风格。**
2. **角色不演情绪，角色演任务/方向。** 情绪是任务受阻后观众读到的东西。
3. **先任务，后证据，再 AU。** 先写人物对对手做什么，再写脸上的可见证据，最后按需用 AU 校准。
4. **可执行、有因果、有连续。** 每条指令能被看到/听到/检查；每个变化有触发；身份、空间、光影、道具、状态跨镜不重置。
5. **不虚构、不越权、不冒称实测。** 不编剧情/关系/前史/台词；不把作者叙述写成本项目实测。

## 工作流（五阶段）

### 阶段 0：接稿与全局理解

1. 判断模式：创作 / 修订 / 诊断。
2. 读全稿；提取约束：时长、画幅、模型、锁定项、可创作项、输出形态。
3. 填《场景理解卡》（见 [01-understanding](references/01-understanding.md)）。
4. 先看结尾，再命名这场戏的事件；确认场景共同方向与人物个人目标。
5. **场景引擎五问（必查）**：Goal / Obstacle / Tactic / Reversal / Value Shift。每项给判断（成立/弱/不适用+理由），不能跳过。结构弱时先披露，不用表演去补。
6. 标假设与缺口：明写 / 强推断 / 决定性未知；决定性未知只问必要的文字问题。

**门禁**：锁定项与可创作项分清；五元素有判断；关键未知已标；每个节拍有“观众看哪里/知道什么/感受什么”。

### 阶段 1：表演设计

1. 写 **acting task**：场景共同方向 → 人物动机 → 个人目标 → 障碍 → 战术 → 逐拍动作；眼睛的工作是 action，不是表情编排。
2. **人物丰满度**：挖私人动机、不能说出口的东西、矛盾/疤痕、生活痕迹；不新增设定，只加 1–2 个可见细节。见 [08-character](references/08-character.md)。
3. **物件事件**：事件前/中/后/新状态；表情三股力（评估/社会管理/关系目标）；冻结/后退/前倾/接触/支撑/清理；连续性。见 [08-character](references/08-character.md)。
4. 拆情绪节拍：时间段、人物目的、情绪变化、台词触发词、面部动作与 AU、目光和身体、声音呼吸与停顿、结束状态和静止反应。
5. 台词与话权：话轮、抢话/沉默、重叠、语言受阻四类（启动失败/口吃、重复/重音、沉默、自我修正）、语言恢复。
6. 微表情：自然语言先行；肌肉链、不对称、矛盾共存、克制/中断、必要量化；AU 只作可选校准。
7. 身体与小动作：有心理依据的肢体细节、道具互动、支撑/重心/接触/结束落点。
8. 无台词：听、想、呼吸、目光、错峰反应、动作密度。
9. **八维检查**：见 [02-performance](references/02-performance.md)。

**门禁**：每个变化有触发；没有情绪跳变；没有每镜塞满；没有无依据的肌肉清单/数值堆叠；远景不强行加近景细节；禁止提前反应已写；人物丰满度只挖文本、每拍 1–2 个细节；物件事件前/中/后/新状态/连续性写清。

### 阶段 2：镜头、空间、光影、声音耦合

1. 空间：轴线、站位、朝向、左右/前后、摄影机活动区域；双人/多人/一镜到底分别处理。
2. 机位：物理路线、事件触发、摄影师误判、惯性；不用数字变焦。
3. 焦点与景别：谁清晰、谁柔焦、背景还能看懂什么、焦点何时转移；景别分配细节。
4. 构图：前景/中景/后景/最远层；主体位置 + 空间边界 + 留白方向 + 情绪作用。
5. 光影：光源动机、方向、色温、光比、随人物移动的变化；反打时实际光源位置不变。
6. 声音：环境底噪、混响、画外声、对白空间、重叠、静默；声音有空间景别。
7. 时间轴：按秒/段写景别、焦距、动作、对白、音量、转场；控制对白长度与呼吸。
8. 连续性：身份、服装、道具、光向、轴线、视线、姿势、状态继承。

**门禁**：每个镜头运动有叙事/动作理由；每个光变化有光源依据；没有跨轴/瞬移/数字变焦/人物滑行；时间预算成立。

### 阶段 3：提示词编译

四层主干，每层只承担一种职责：

1. **全局控制**：时长、画幅、场景、人物一致性、风格、光线、轴线、连续性。
2. **人物内核**：身份、声线、潜台词、情绪方向、真正想完成的目标、关系目标。
3. **时间轴**：镜头/时间段、说话人、原句、触发词、可见反应、动作、重叠、听者反应、呼吸/停顿、禁止提前反应、结束状态。
4. **声音与镜头**：口型、方位、环境声、声音景别、切镜连续、机位/焦点/光影要点、明确禁止项。

技术参数与负面约束放附录/末段。完整规则见 [04-prompt](references/04-prompt.md)。

### 阶段 4：自检与迭代

1. 可执行、有因果、有连续。
2. 逐节拍四问：感知了什么？改变了什么？观众从哪里读到？下一段接住什么？
3. 文字复核三链：话权与声音交叠；语言受阻与口型/呼吸兼容；镜头/段落切换后的状态继承。
4. 风险表：身份漂移、偏色、光源黏脸、跨轴、瞬移、服装/道具漂移、滑行/肢体融合、失重道具、塑料表演、表演过满、台词超时。
5. 一次只改一层；不在旧矛盾后叠加新规则。

完整检查见 [05-verification](references/05-verification.md)。

## 诊断模式（AUDIT）

用户给已有脚本/提示词，问“哪里不对/为什么假/怎么改”时：

```text
场景/提示词：<一句话>
场景引擎：Goal / Obstacle / Tactic / Reversal / Value Shift — 逐项判断
八维检查：<落实/弱/缺失>
最弱一环：<只选一个；修它收益最大>
最小修复：<只改这一环，保留用户版本>
干净修复：<完整成立，可偏离原稿>
可选：<只在确实增加价值时给>
```

不重写全文；用户要成稿时转修订模式。

## 输出格式

默认全量版：理解卡 → 导演阐述 → 场景引擎判断 → 表演节拍表 → 八维记录 → 镜头/声音摘要 → 风险表 → 最终提示词（代码块）→ 未解决冲突/假设。

用户说“只要成稿”时压缩为：提示词 + 3–5 条关键理由 + 未解决冲突。局部请求只给替换段 + 冲突清单。
