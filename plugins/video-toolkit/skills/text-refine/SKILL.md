# Text Refine

Claude 直接校准 ASR 转录文本，修正错别字、同音字、专业术语；非中文自动翻译为中文后再校准。

**无需额外依赖** — Claude 自身就是校准引擎。

## 铁律：输出格式必须与输入一致

| 输入 | 输出 | 文件名 |
|------|------|--------|
| `.srt` | `.srt` | `{原文件名}_refined.srt` |
| `.md` | `.md` | `{原文件名}_refined.md` |
| `.txt` | `.txt` | `{原文件名}_refined.txt` |

**为什么这条最重要**：SRT 是带时间轴的字幕交换格式，播放器、剪辑软件以及 `add-subtitle` 等下游 skill 都按 SRT 解析。把 SRT 改写成 Markdown 会丢失逐条时间轴，直接破坏下游流程。格式不是"展示样式"，是契约——**只改文字，不动结构**。

- 不要给 SRT 加标题、摘要、加粗、引用块或分隔线
- 不要改扩展名，不要"因为 Markdown 更好读"就转换格式
- 只有用户明确要求"整理成文章 / 转成 Markdown"时才改变格式

## 工作流程

1. 读取用户指定的字幕/文本文件（SRT / MD / TXT），**记住输入格式**
2. 自动检测语言
3. 非中文 → 翻译成中文 → 校准；中文 → 直接校准
4. 按原格式写回同目录：`{原文件名}_refined.{原扩展名}`
5. 用独立 agent 复检信达雅（见"审校"节），按报告修订

## 首次检查

无额外依赖，跳过。

## 翻译标准（非中文 → 中文）

视频翻译要"视听成立"，不只是"文本成立"：字幕一闪而过，观众要同时看画面、读文字、听声音，没有回溯重读的机会。时间轴不可改，所以一切约束最终都落在**译文字数与断句**上。

### 时空同步：译文长度由时间轴预算决定

- 阅读速度（CPS）：中文每秒 3~5 字为舒适区（参考：西文 15~17 字符/秒），硬上限 7 字/秒。落笔前先看该条时长对照速查表——超出预算就**减词**，而不是硬塞；连硬上限都装不下就拆条

  | 条目时长 | 1 秒 | 2 秒 | 3 秒 | 4 秒 | 5 秒 | 6 秒 |
  | --- | --- | --- | --- | --- | --- | --- |
  | 舒适上限 | 5 字 | 10 字 | 15 字 | 20 字 | 25 字 | 30 字 |
  | 硬上限 | 7 字 | 14 字 | 21 字 | 28 字 | 35 字 | 42 字 |
- 短条（≤2 秒）只译核心信息；well / you know / I mean 等口头禅、填充词一律省略
- 单条展示尽量不超过 6~7 秒；原文时间轴超长（如 Whisper 整段 15 秒一条）时按下方"拆分触发"拆条
- 拆分拆点必须落在**意群边界**（标点、从句边界），不把一个词组切在两条里

### 版面：一行一个意群

- 每条 ≤2 行，单行 14~18 个汉字为舒适区（硬上限 20），西文单行 ≤40 字符
- 换行按语法意群断：不在"的/了/和/在"前后生硬切断，不让定语和中心语分家
- 换行与减词的正反例见 `references/line-break-cases.md`（4 个影视台词案例 + 1 个中文 ASR 断句案例），拿不准断哪时先读它

### 动态对等：口语化、减词、即时可懂

- 用短句、主动句、生活化口语；避免嵌套从句、"被"字连用、书面腔
- 英文长句可拆成中文两三条短句，语序按中文习惯重排，不逐词直译
- 画面已交代的信息（挥手告别、路标、动作特写）在台词中弱化或精简，把阅读精力留给增量信息
- 画面中的关键文字（UI 界面、招牌、信件）若影响理解，译作【画面：…】标注
- 中英夹杂（技术/科普视频常见）：句子主体译成中文，术语与产品名保留原文——Cursor、React、"这个 API"不硬译；只有整句英文才整句翻译
- **减词不减戏**：删的是信息冗余（填充词、直译腔、画面已交代的内容），不是角色语气——"吧/呢/嘛/哦"等中文语气词和人物口头禅是人设的一部分，保留

### 本地化与文化适配（Transcreation）

- 谐音梗、文化暗喻直译会一头雾水：转化为中文受众能秒懂的对应说法；无对应就意译含义
- 计量单位（英里/华氏度）按受众习惯换算或保留，全片统一
- 角色人设统一：同一说话者全片用词一致；不同身份、年龄、情绪的人说话各有其语，避免人人都是同一种"AI 译文腔"

## 断句与减词案例（外置 references）

正反例全文见 `references/line-break-cases.md`：案例 1~4 为影视台词（意群断句 ×2、减词、动作化拆解），案例 5 为中文 ASR 流水句断句。断句总纲一句话：**行尾是自然的思维停顿点**——主谓、动宾、介宾、固定短语尽量留在同一行，不把助词孤立在行尾或下一行行首。

### 断句减词核对清单

产出每条双行字幕前过一遍：

- **行长平衡（梯形排版）**：双行尽量排成"上短下长"或"上长下短"的梯形，避免上行 16 字、下行仅 2 字的"吊靴"排版
- **剔除虚词**：检查并减少非必要的"的""了""着""地"，以及"某种程度来说""显而易见"等机械对译填塞语
- **断句看标点**：字幕行尾尽量不出现逗号——第一行末尾若是自然换行，直接切分即可，无需在行末强行加逗号

## 校准规则

### 核心原则

- **基于全文主题和语义校准**，不孤立地校对每个句子
- 同音字的选择、术语的确定都要基于上下文语境
- 先理解全文主题，再逐段校准

### 删除 Whisper 冗余词

Whisper 经常误添加无意义的"叫做"、"所谓的"等词，必须删除：
- "叫做被抑制" → "被抑制"
- "所谓叫做这个功能" → "这个功能"
- **原则**：删除后句子仍通顺就不要加回任何词

### 清理 Whisper 重复伪影

Whisper 常在段落末尾或段落之间产生整句重复，必须清理：
- "我增加了一对新婚夫妇" × 5 → 保留 1 次
- "观看观看观看观看观看" → "观看"
- **原则**：同一短语连续重复 3 次以上，保留 1 次；保留后检查语义是否通顺

### 清理平台水印和广告

从视频平台下载的视频常包含水印文字被 ASR 识别，必须删除：
- "优优独播剧场"、"YoYo Television Series Exclusive" → 整段删除
- "Extension"、"解锁更多"等平台提示语 → 删除
- **原则**：明显非视频内容本身的广告、水印、平台提示语一律删除

### 清理 Whisper 幻觉内容

Whisper 在中文音频中常幻觉出英文或无意义内容，尤其在段落边界：
- 中文视频中突然出现的无关英文短句（非引用、非专有名词）→ 删除
- 段落末尾的 "stylestyle"、"yeah yeah yeah" 等无意义重复 → 删除
- **原则**：内容与上下文语义无关且无法合理解释的，视为幻觉并删除

### 添加标点符号

原始 ASR 输出通常无标点，校准时必须补充：
- 句号（。）、逗号（，）、问号（？）、感叹号（！）、冒号（：）、分号（；）
- 作品名用书名号（《》），重要概念首次出现可用引号（""）
- 人名中间加分隔号（马丁·斯科塞斯）
- 省略号用标准中文省略号（……）
- **原则**：标点服务于可读性，不改变语义和节奏

### 同音字/错别字纠正

根据上下文语义判断。各领域常见 ASR 错误对照表（通用/影视/科技/医疗）外置于 `references/asr-corrections.md`——按"视频类型自动检测"的结果查对应段落，表外可疑词按"同音/近音 + 语境"自行判断。

### 不改变原意

- 不添加内容
- 专有名词和产品名称必须准确
- 不随意更改句式

## 视频类型自动检测

读取文本前 30 段样本，根据关键词判断类型并调整校准策略：

| 类型 | 关键词示例 | 校准重点 |
| --- | --- | --- |
| **影视** | 镜头、导演、摄影、景别、分镜、推拉摇移、视点、调度 | 人名片名准确、影视术语准确、外文片名翻译 |
| **医疗** | 膈肌、骨盆、康复、腹内压、骶骨 | 解剖学术语、医学术语准确 |
| **科技** | 代码、API、Cursor、Python、React | 产品名称、技术术语准确 |
| **财经** | 股票、基金、K线、涨停板 | 财经术语、公司名称准确 |
| **通用** | 其他 | 常见 ASR 错误纠正 |

检测到特定类型后，校准时优先使用对应领域的术语。

## 分段处理

- 短文件（≤200 段）：一次读取，整体校准
- 长文件（>200 段）：分段处理，每段保留前段最后 5 句作为上下文衔接，确保跨段语义连贯

### 长文件落盘节奏（防止单响应超限被终止）

subagent 单条响应有 32000 output token 硬上限，超限直接终止且不重试（报错 `exceeded the 32000 output token maximum (max_output_tokens)`）。实测 8 个翻译 agent 中 6 个因"一条响应里塞多段译文 / 一次写完整个文件"死于此。因此无论当前会话自己处理还是派 agent，落盘一律按此节奏：

1. 读一段：输入每次 Read 约 400-500 行（约 100-120 条），不要先通读全文
2. 译一段：每段 ≤50 条，译文 ≤8KB
3. **一条响应只发一个落盘命令**：heredoc 追加（第一段 `cat > 文件 <<'SRT_EOF'`，后续段 `cat >>`），等命令结果回来再译下一段
4. 把多段攒进一条响应"省事"，那条路直通 32k 终止

## 多文件批处理（并行上限 3）

用户给出一个目录或多个文件时，按批派 subagent 并行处理：

- **同时运行的 refine agent 最多 3 个**：8 个文件就分 3+3+2 三批，一批全部收到完成通知后再派下一批
- 并行超过 3 个会摊薄生成吞吐（每个 agent 都变慢），并放大单响应超限的失败率
- 每个 agent 的 dispatch prompt 必须自带三样：输出契约（未拆分条目时间轴原样复制、序号连续递增、UTF-8 无 BOM）、上一节的落盘节奏约束、该视频的领域术语表（按"视频类型自动检测"节判断，基础词表见 `references/asr-corrections.md`）
- 文件 ≤2 个时不派 agent，当前会话直接顺序处理

## 输出规范

### 输入是 SRT（保持 SRT）

逐条写回，结构与时间轴原样保留：

```srt
1
00:00:00,000 --> 00:00:16,800
校准后的字幕文本

2
00:00:16,800 --> 00:00:22,559
下一条字幕
```

- 序号、时间轴（`HH:MM:SS,mmm --> HH:MM:SS,mmm`）**一个字都不改**
- 只替换每条的字幕正文
- 每条 ≤2 行，单行 14~18 个汉字为舒适区（硬上限 20），换行按意群断（见"翻译标准"）
- 拆分触发：译文超出 2 行版面，**或单条时长超过 ~7 秒**；拆点落在意群边界，原时间段按文字长度比例切分，总时长和前后衔接保持不变
- 多条短句保持原样，不要为了"排版好看"合并；跨条断句要保证连起来读通顺
- UTF-8 无 BOM，条与条之间空一行
- 不添加任何 Markdown 标记

### 输入是 Markdown 或 TXT（保持原格式）

- Markdown：标题层级、列表、代码块、引用等结构原样保留，只校准文字
- TXT：保持纯文本分段，不引入 Markdown 语法
- 默认不做"重排版"；只有用户明确要求美化/重组时，才按下面的规则调整结构

#### 美化规则（仅在 MD/TXT 且用户要求时使用）

- **层级标题**：按主题添加 `##` / `###`，标题简洁反映主旨
- **加粗关键术语**：专业术语、核心概念首次出现加粗，后续不重复加粗；人名、作品名不加粗（作品用《》）
- **列表化枚举**：分类、类型、要点转为有序或无序列表
- **分段**：按语义单元分段，每段 3-8 句，话题转换必须分段
- **引用块**：仅对重要引用、金句使用 `>`
- **分隔线**：主要章节之间用 `---`

## 审校：独立 agent 复检信达雅

译者和校对不能是同一个"人"——翻译 agent 对自己的错误是盲的。refine 完成后，由**另一个独立 agent**（不沿用翻译 agent 的上下文）对照原文与 `_refined` 输出复检，以信达雅为纲：

| 维度 | 检查什么 | 典型问题 |
| --- | --- | --- |
| **信**（忠实） | 核心信息、逻辑、数字、否定词、术语与原文一致；不漏译、不编造 | 否定词漏译把意思翻反；200 万译成 20 万；产品名错拼 |
| **达**（通达） | 合乎中文表达习惯、无翻译腔；跨条连读通顺；字数不超 CPS 预算 | 定语从句直译成"被"字长句；相邻两条接不上 |
| **雅**（得体） | 文体与语气契合视频类型和说话者人设，全片语域统一 | 教程视频译出新闻腔；所有角色一个腔调 |

执行要点：

- 审校 agent 拿三样东西：原文文件、`_refined` 文件、该视频的类型与术语表
- ≤250 条全量对比；更长的文件抽头/中/尾各约 40 条精查，并对全片做术语与数字扫描（产品名、`$`、`%`、次数在两侧是否一致）
- 报告只列**问题条目**，按严重度分级：**信-必修**（歪曲/漏译/编造/数字错误）、**达-应修**（翻译腔/断句/CPS 超预算）、**雅-可选**（语域/风格）；每条注明：序号、原文、现译、建议改法
- 报告直接在返回结果给出；条目过多则写入 `{原文件名}_review.md`，控制在 ≤8KB
- 主会话按清单逐条修订（Edit 改对应条目，不重跑整个文件）；信级问题修完后对修订条目做一次快速复核
- 并行调度：审校可以与下一批翻译跨批并行（审上一批、译下一批），但翻译并发仍守"并行上限 3"；审校 agent 只读文件、只出报告，不占翻译名额

## 与其他 skill 配合

```text
video-downloader → audio-transcribe → text-refine → add-subtitle
    下载视频           转录字幕          校准字幕        叠加字幕
```

text-refine 的输出格式与输入一致，所以 SRT 校准完可以直接交给 `add-subtitle`（它约定每条 ≤12 字——确定要叠加字幕时，翻译阶段就按每条 ≤12 字拆条）；交给 `video-tts` 配音时，时间对齐由它的语义合并（`--merge-plan`，读全文按语义分组）兜住——按语义段合并成块后整段朗读，配音语速预算约 4 字/秒（另计标点停顿），比字幕阅读预算宽松，refine 不必为配音额外减词。

## 示例

```text
用户: 校准这个字幕 video.srt          → video_refined.srt
用户: 翻译并校准 audio.srt            → audio_refined.srt
用户: refine 一下这个 md 文件         → xxx_refined.md
用户: 把这份字幕整理成文章            → 用户明确要求时才输出 .md
用户: 这个文件夹里的 srt 都润色       → 多文件批处理：分批派 agent，并行 ≤3
```
