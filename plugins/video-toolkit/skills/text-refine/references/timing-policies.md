# 时间轴策略与阅读指标口径

按需读取：任务为默认校对/翻译/精简时可只看「preserve 契约」与「统计口径」；用户明确要求重新分段时读全文。

## preserve 契约（默认，三种任务通用）

1. 条目数量、条目顺序与输入一致，保留原序号；输入序号不连续或重复时不擅自重编号（管线按源位置生成 `entry-000001` 这类稳定 ID 区分，重复/断续仅诊断）。
2. 每条起止时间不变；时间轴行整行原样保留，包括合法的坐标等附加定位信息（`X1:… X2:…`）。
3. 只编辑正文；不添加标题、摘要、报告、Markdown 围栏或说明文字。
4. 不因单条超过 7 秒、两行或某个字数预算自动拆条、合并或平移时间。
5. 原有合法样式标签（`<i>`、`<b>`、`<font …>` 等）与控制信息保持有效：可编辑标签内的可见文字，标签本身不当正文纠错（提交时管线按标签多重集合比对）。
6. 输出 UTF-8 无 BOM；允许规范化正文换行与条目间空行，但不得以编码规范化为由改变时间或条目映射。

程序保证（无需模型自证）：validate 会逐条比较全部时间轴行、序号行与条目覆盖恰好一次；模型输出里根本没有时间字段可填。

## resegment（仅用户明确要求）

启用条件：用户提出「重新分段」「拆条」「重做时间轴」，或明确提出分段诉求。任务中记录 `--timing resegment --timing-reason <来源>`。

### 时间来源三分支

| 时间来源 | 处理要求 |
| --- | --- |
| `word-timestamps`：与当前音频及文本相匹配的词级时间戳 | 结合意群选择拆点，使用真实时间边界（首选） |
| `audio-align`：有源音频且已接入对齐能力 | 需要重新对齐时复用现有能力；译文不能直接套用原语言词时间逐字对齐 |
| `srt-estimate`：只有句级 SRT | 仅当用户明确接受估算后才使用：在原时间范围内按文本权重分配，输出标明估算，不得称为精确对齐 |

用户要求精确对齐而输入/能力不足 → 说明缺少什么（词级时间戳/源音频/对齐工具），保持默认校对可执行，不暗中降为估算。本 skill 不新增强制对齐模型、不安装语音依赖。

### 输出要求

- 连续的新序号 1..N；完整的源条目 → 目标条目映射；合法起止时间。
- 拆出的条目不得超出其源条目的时间范围；不得因四舍五入产生零时长或反向时间。
- 合并或跨条调整需要用户相应明确授权。
- 在总时长不变的前提下拆条不会降低平均阅读速度——「超过 CPS 就拆条」不是降低信息密度的办法。

### 提交格式（与 preserve 不同，见 file-interface.md）

```json
{
  "chunk_id": "chunk-0001",
  "mode": "resegment",
  "items": [
    {"source_ids": ["entry-000001"], "start": "00:00:01,000", "end": "00:00:04,000", "text": "拆出的第一句"}
  ]
}
```

约束（submit 时程序校验）：`source_ids` 并集恰好覆盖本块全部源条目；每条 `start < end`；时间窗落在其源条目 [min(start), max(end)] 内；新条目按时间序不重叠（边界相接允许）。不能借正文中的换行偷偷创建新条目。

## 阅读与排版指标口径

原有中文数值保留为**可配置检查参考**，不是所有题材和语言都适用的绝对标准，不新增复杂平台排版预设：

- CPS（每秒字符数）舒适区：中文 3~5 字/秒，硬上限 7 字/秒（参考值；西文经验值约 15~17 字符/秒）。
- 行长：中文单行 14~18 字舒适（硬上限 20），西文单行 ≤40 字符；每条 ≤2 行。
- 超标处理：形成提示或审校项（可选级），**不能因此删除事实、拆条或改时间轴**。

### 统计口径（两种都要注明用的是哪个）

| 指标 | 定义 |
| --- | --- |
| `han_count` | 汉字数量（不含标点、数字、拉丁字符） |
| `visible_char_count` | 移除合法样式标签及空白后的可见字符数，含标点、数字和拉丁字符 |

「14 个汉字」与「14 个可见字符」不得混用；英文、混合语言和含代码的文本不套用中文汉字预算。行尾标点与两行平衡属风格偏好，低于语义、语法与信息完整性。

翻译时数字写法可能变化、单位可能按用户要求换算，不能仅凭字符不一致判定数值错误；可程序化比较的数值做辅助检查，语义等价与单位换算仍须内容审校，默认不换算单位。
