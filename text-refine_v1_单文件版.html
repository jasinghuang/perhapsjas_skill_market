02

铁律：输出格式 = 输入格式

11/2 终版最重要的一次自我修正
输入输出文件名
.srt.srt（完整保留时间轴）{原文件名}_refined.srt
.md.md{原文件名}_refined.md
.txt.txt{原文件名}_refined.txt
理由原文：SRT 是带时间轴的字幕交换格式，播放器、剪辑软件与 add-subtitle 等下游 skill 都按 SRT 解析。格式不是"展示样式"，是契约——只改文字，不动结构 三不：不给 SRT 加 Markdown 标记 · 不改扩展名 · 只有用户明确要求才转格式

SRT 逐条写回规范（prompt 原文要点）

  • 序号、时间轴 "一个字都不改"，只替换每条正文
  • 每条 ≤ 2 行、每行约 20 个中文字符以内
  • 原文一条过长可拆多条，按文字长度比例切分时间段，总时长与前后衔接不变
  • 多条短句保持原样，不为"排版好看"合并；跨条断句连读通顺
  • UTF-8 无 BOM · 条间空一行 · 不加任何 Markdown 标记

惊人的祖先条款 —— 写在提示词里的后世机制

  • "一个字都不改" → ④代 render_srt 逐字保留 → v2 硬不变量"时间戳逐字节相同"
  • "按文字长度比例切分时间段" → ⑤代 schedule() 字符范围线性插值
  • "每行约 20 字" → DEFAULTS line_chars = 18
  • "多条短句保持原样不合并" → v2 "条数 == N" 断言
  • "格式是契约" → 整个结构守护体系的世界观起点
管线因此延长一格：video-downloader → audio-transcribe → text-refine → add-subtitle——格式契约保住了，输出才能直连下游叠加字幕

六类校准规则

全部是写给 Claude 的话，不是代码
RULE 01

删除 Whisper 冗余词

Whisper 常误添加无意义虚词

叫做被抑制→被抑制
所谓叫做这个功能→这个功能
删除后句子仍通顺，就不要加回任何词
RULE 02

清理重复伪影

段落末尾或段落间产生整句重复

"我增加了一对新婚夫妇" × 5→保留 1 次
观看观看观看观看观看→观看
同一短语连续重复 3 次以上保留 1 次，保留后查语义通顺
RULE 03

清理水印与广告

平台水印被 ASR 识别进字幕

优优独播剧场→整段删除
YoYo Television Series Exclusive→整段删除
非视频内容的广告、水印、平台提示语一律删除
RULE 04

清理幻觉内容

中文音频里幻觉出英文或无意义内容，常在段落边界

中文视频突现无关英文短句→删除
stylestyle · yeah yeah yeah→删除
与上下文语义无关且无法合理解释的，视为幻觉并删除
RULE 05

添加标点符号

原始 ASR 输出通常无标点

句读全套→。 ， ？ ！ ： ；
作品 / 人名 / 省略→《》 · 马丁·斯科塞斯 · ……
标点服务于可读性，不改变语义和节奏
RULE 06

同音字 / 错别字纠正

按领域分组硬编码在提示词里

地域→阈值通用
试点→视点影视
Crawl→Cursor科技
肃部→腹部医疗
不改变原意：不添加内容、专名必须准确、不随意改句式

05

分段处理

长文件上下文衔接的雏形

≤ 200 段

  • 一次读取，整体校准——全文语义优先的最简实现

> 200 段

  • 分段处理，每段保留前段最后 5 句作为上下文衔接，确保跨段语义连贯
  • 没有批次文件、没有逐段校验、没有断点——上下文携带全凭模型自觉
→ 演化对照：这个"前段尾巴做衔接"的思想，四代之后变成了 v2 批次材料里的 prev_batch_tail_translation 字段

输出规范

SRT 是默认路径 · 美化被降级为可选

SRT：逐条写回（默认路径）

1
00:00:00,000 --> 00:00:16,800
校准后的字幕文本

2
00:00:16,800 --> 00:00:22,559
下一条字幕
  • 序号与时间轴 "一个字都不改"，只替换正文
  • 超长一条可拆多条、按文字长度比例切分时间段；多条短句不合并
  • UTF-8 无 BOM · 条间空行 · 不加任何 Markdown 标记

MD / TXT：结构原样保留

  • Markdown 标题 / 列表 / 代码块 / 引用结构原样，只校准文字
  • TXT 保持纯文本分段，不引入 Markdown 语法
  • 美化规则仅在 MD/TXT 且用户明确要求时使用：层级标题 · 术语首现加粗 · 列表化枚举 · 每段 3~8 句 · 引用块仅限金句 · 章节间分隔线
  • 五月版"把字幕文档化成精美 Markdown"的整章输出规范在终版被删除——那个方向已被铁律否定
终版示例：校准 video.srt → video_refined.srt · 翻译并校准 audio.srt → audio_refined.srt · "把这份字幕整理成文章" → 用户明确要求时才输出 .md
07

遗产与局限

它定下的方向 · 它埋下的雷

活到今天的遗产

  • 格式契约铁律——"输出 = 输入 · 只改文字，不动结构" → preserve 模式逐字保留与 v2 结构守护体系的世界观起点
  • 全文语义优先——"基于全文主题校准，不孤立校对单句" → 各代"先理解完整句意"的源头
  • 领域自适应——视频类型检测换术语策略 → v2 术语探测 + style_note
  • 分段 + 上下文衔接——前段末 5 句 → v2 的 prev_batch_tail_translation
  • 触发词路由——16 个触发词让 skill 可被自然语言唤起
  • 零依赖哲学——"Claude 自身就是引擎" → 后续各代坚持纯标准库

被后四代逐一修掉的雷

  • 守护只存在于措辞里——"一个字都不改"没有任何代码验证：模型若写坏条数或时间戳，无从发现 → 周末 Python 化（②~⑤代）解决的第一个问题
  • 翻译是"顺手翻"——无术语锁、无预算、无审校、无门禁 → 正是 v2 重建的主战场
  • 规则硬编码在 prompt——影视/医疗错字表写死在文档里，不可参数化、不可测试 → 后续移入 references 与代码参数
单文件时代小史：五月版"SRT → Markdown 文档化"（产物不可回灌播放器）→ 11/2 终版用铁律否定该方向——六个月内纯靠 prompt 迭代，完成了一次重要自我纠错
