# video-tts 块级对齐配音(方案 C 调整版)

## Context

用户反馈:refine 后的 SRT 交给 video-tts 配音"节奏赶"。根因:engine 逐条独立合成,每条必须塞进自己的字幕窗口,`plan_fit` 静默加速 ≤1.15x、警告加速 ≤1.30x、再超截断;条间空档造成顿挫。用户拍板**方案 C**:按语义段合并成块(块窗口 = 首条 start → 末条 end),段内自然朗读;**块级文件生成放在 video-tts**(配音才需要,text-refine 保持纯字幕校准器)。

探索发现:`--merge-plan`(Claude 语义分组,SKILL.md:94-128)+ `load_merge_plan()`(merge_plan.py:36,块窗口构造已实现)**已存在**。本计划补全缺失部分,不重造。

## 改动清单

### 1. `merge_plan.py` — 新增机械分组兜底 `group_cues()`
- 签名:`group_cues(cues, *, gap_threshold=0.8, max_seconds=18.0, max_chars=80) -> list[Cue]`
- 规则:条间 gap ≥ `gap_threshold` 断块;加入下一条将超 `max_seconds`/`max_chars` 时断块,且断点优先回退到最近的句末标点(。！？;);单条自成一块也允许(不像语义计划要求 3~8 条)
- 复用现有 `_join_texts`(merge_plan.py:23,缺标点补",")和合并 Cue 构造(:96-105,`start=first.start, end=last.end, next_start=下一块首条 start`)

### 2. `srt_parse.py` — 新增 SRT 写出
- `format_timestamp(seconds) -> str`(HH:MM:SS,mmm,注意逗号毫秒)
- `write_srt(cues, path)`:序号重排 1..N,UTF-8 无 BOM(现有代码只解析不写,全新增)

### 3. `skill_main.py` — `--align` 入口 + 块级文件落盘
- `build_parser()`(:55-151)加 `--align {cue,block}`,默认 `cue`(保持现状,choices 写法照 :68-72 `--provider`)
- 分组执行点在 :577-583 现有 `--merge-plan` 块处:
  - 传了 `--merge-plan` → 走语义计划(现状,无论 align 值;计划优先于机械分组)
  - `--align block` 且无计划 → `group_cues()` 机械分组,打印 `合并: N 条 → M 组(机械分组)`
  - `--align cue` 且无计划 → 现状逐条
- **块级文件**:任何分组生效时,写 `{out_prefix}.dub.srt`(与 `.dub.wav` 命名一致),打印一行 `块级字幕: <path>`;不分组不写。`--dry-run` 预览(:386-413)自动展示合并后条目,无需改
- engine、track_build、mux、providers **零改动**(块=普通 Cue)

### 4. `video-tts/SKILL.md` — 流程理顺
- 决策表 :74 行、执行步骤 3-4(:87-88)、语义合并节(:94-128):补"无计划时 `--align block` 机械兜底"和 `_dub.srt` 输出说明;步骤 4 的 dry-run 检查改为看 `_dub.srt`/预览确认无半句切割
- 参数表(:554 附近)加 `--align`;错误表无需新增(机械分组无用户输入文件)

### 5. `text-refine/SKILL.md` — 修正错误声明
- "与其他 skill 配合"节:"每秒 3~5 字的阅读速度预算正好也是配音语速预算,译文长度天然匹配口型时长" → 改为:字幕时间轴是阅读节奏;配音对齐由 video-tts 的语义合并/块级对齐处理,配音语速预算 ≈ 4 字/秒(另计标点停顿),减词压力比字幕更宽松

### 6. 测试
- `tests/test_merge_plan.py` 追加 `group_cues` 用例:gap 断块、时长/字数上限断块、断点回退句末标点、单条成块、整段一块
- `tests/test_srt_parse.py` 追加 `write_srt`/`format_timestamp` 用例(往返:parse(write(cues)) 时间轴无损)
- `tests/test_cli.py` 追加:`--align` 解析与默认值;`--align block` 无计划走机械分组(仿 `_patch_run` :355-364 模式,断言 `.dub.srt` 生成且条数减少);`--align cue` 行为不变;`--merge-plan` + `--align block` 共存时计划优先

## 边界决策(已定,可驳回)

- 默认 `--align cue`:不改变既有调用行为;SKILL.md 继续推荐 Claude 生成语义计划
- `--merge-plan` 与 `--align block` 同时出现:计划优先(语义质量 > 机械)
- `_dub.srt` 分组生效即写、不提供关闭开关(文件小、可检查、可给 add-subtitle 复用)
