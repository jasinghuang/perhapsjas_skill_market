# 章节开发指引（每章开发必读——单一入口）

Phase 4 写每一章，只读这一份就够。所有章节级约束都在这里；组件/token 的
具体词表在 [`LIBRARY.md`](LIBRARY.md)，门禁红了查 [`GATES.md`](GATES.md)。

## 这是视频，不是 PPT

判断每步做对没有的标准：

- **不像 PPT**——观众在看视频，不是翻页幻灯。无页眉页脚，突出主视觉元素
- **看起来舒服**——配色/字体/节奏让人放松；无大片纯文字、无小字
- **有视觉冲击**——画面在**演事情**，不是文字堆砌；关键元素随进度逐步推进
- **财报视频再加一条**：画面上的每个数字**都必须可溯**（来自 article.md 的
  真实数据，不是编的），且**单位/口径标在画面上**（观众看到"843"必须同时
  看到"亿元"与"同比"）

---

## 视觉演示底线：每章必须有"在演"的演示元素

> **这是底线。** 每章至少 1~2 处"在演"的演示。**整章纯文字 = 验收不过 = 重做。**
> 演示元素**只能来自组件库**（44 个组件，词表见 LIBRARY.md）——不要自己手写
> CSS 动画去"演"，手写的进不了 seek 渲染。

财报解读最常用的"演"（全部是现成组件）：

- 数字在递增：`Counter` / `HeroNumber`
- 条在生长（营收趋势/分部对比）：`BarGrow` / `YearBarGroup`
- 环在填满（占比/毛利率）：`DonutMeter`
- 对比被一刀切开（同比/环比/竞对）：`SplitCompare`
- 表格逐行亮（报表明细）：`Table` + `StaggerRow`
- 趋势线自绘（收入曲线）：`PathDraw` / `EChart`
- 清单逐项揭示（风险点/看点）：`RevealList` / `StepSequence`
- 结论砸出来（判断/风险提示）：`MarkerBlock` / `PostIt`

**怎么组合都行——但每章必须用，且来自组件库。**

## 逐步揭示，禁止一次全展示

**先澄清一个模型问题**：step 仍然是底层模型（`chapter = f(step)` 纯函数），但
**推进是音频驱动的自动播放**——没有点击推进。所以你设计每步时想的不是
"观众什么时候点"，而是：

- **这一步的画面演多久**（动画窗口，由组件档位定）
- **口播念到哪一句时，画面演到哪**（音画同步）
- **这一步停留多久**（停留垫，Phase 3 已在 timing.json 定过，Phase 4 可微调）

> 当口播在说"第一是 X、第二是 Y、第三是 Z"这类**清单**时，**严禁**一个 step
> 把 X/Y/Z 全部 stagger 上来。

正确做法：**一项 = 一个 step**。X 在自己那步独自亮起；讲到 Y 时 X 灰化保留
作上下文 + Y 亮起；讲到 Z 时 X/Y 灰化 + Z 亮起。

**判断标准**：讲者会一个一个念出来吗？会 → 必须逐个揭示。财报场景最常见：
"营收涨、利润跌、现金流也跌"——三个结论是三步，不是一屏三张卡。

## 内容取舍：抓重点，不要原文搬运

- **口播**负责把数据线性讲清楚
- **画面**负责把节拍重点放大

财报的每个 step 只挂这个节拍**最值得放大的 1~3 个东西**——一个 hero 数字 /
一组对比 / 一张小表 + 必要的演示。不要把报表整页搬上屏，那是把 PDF 截图了。

## 双源：节奏跟口播稿，细节回原报告

- **节奏/顺序/节拍切分**跟 `script.md`（关键顺序不能乱；真相源 `narrations`
  就是由它机器生成的，你不得手改）
- **画面细节/数据/引用**回 `article.md`（原始财报/文章）抽——那里面才有
  完整数字、分部明细、风险原文

`outline.md` 每章首段有「信息池」做参考，但实现时**必须回去翻 `article.md`
本章对应段落**，把细节挂上画面，让**画面信息密度 > 口播信息密度**。

> 只用口播稿的内容做章节 = 屏幕把口播打字打了一遍 = PPT。财报场景这条更硬：
> 口播只能念 3 个数，画面可以把整张分部表挂出来——**画面补口播没念的细节**，
> 这正是本 skill 的核心价值。

## 视觉怎么定：三层正向来源 + 一张负面清单

**风格从来不是"避开什么"定出来的，是三层正向来源拼出来的**：

| 层 | 来源 | 章节的权力 |
|---|---|---|
| **气质** | **主题**（creative-mode，用户已拍板）：奶油纸底 / 四色强调（橙粉绿黄）/ Archivo Black + Noto Sans SC 900 / 4px 墨框 / 硬偏移阴影 / Bauhaus 网格 + 朋克杂志 + 瑞士编辑 | 无权改——所有色值/字体/圆角/阴影走 token，主题换挡全片自动跟随 |
| **零件** | **组件库**（44 个受控组件，词表见 LIBRARY.md） | 只能选组件+档位+变体，禁手写裸样式（#9 门禁） |
| **构图** | **章节层**：组件怎么拼、放哪、多大、每步演什么 | 你的自由发挥区（安全框内） |

**纪律（防原版文档漂移的坑）**：token/组件的**定义**只在 `LIBRARY.md` 与主题文件里——
本章不再重复定义（原版曾在两份文档各写一份 token 契约，后来互相矛盾）。本章只放
**判断规则**（怎么选、怎么拼、什么算越界）。

**下面的指纹清单是负面护栏**——是"别做"清单，不是风格来源。而且其中大部分
（紫粉渐变、深蓝金渐变等）在 token 契约下**根本写不出来**（#2/#6 门禁拦裸色），
列出来是为了防另外两条更隐蔽的越界：**绕过 token 的构图方式**（如用 `<Figure>`
摆一张自带风格的海报图当背景）和**组件选择层面的同质化**（整章一种入场动画）。

**通用指纹**（全部不要）：

- 紫粉/蓝紫对角渐变背景
- 圆角卡片 + 彩色左边框装饰
- 渐变按钮 + 大圆角药丸
- emoji 当图标用
- 假数据/假 logo/假"X 万用户"
- 整章 N 步用同一种入场动画（全场 fade）
- 每步都挂 ken burns/光晕呼吸/持续闪烁
- 每屏右下角都挂 mono 角标/序号

**财报/金融专属指纹**（更要命，观众一眼出戏）：

- 深蓝 + 金色的"金融科技"渐变背景
- 玻璃拟态（frosted glass）卡片
- 假 K 线图 / 假行情大屏 / 假"实时跳动"数字
- 仪表盘 + 雷达图 + 3D 圆环的仪表堆砌
- 金色粒子飘落 / 钱币 emoji / 💰📈 图标
- 虚线箭头 + 齿轮的"流程感"装饰
- 大括号逻辑图 / 无限套娃的思维导图
- 无出处的"行业排名第一""市场份额 80%"大字

缺的数据**承认缺**——用 `<Figure>` 占位卡（按真实比例留位，注明"待补：
XX 数据，来源年报第 X 页"）。**没有就承认没有**，比 fake 强一百倍。素材清单
交付时主动告诉用户："本章还缺这些"。

> 门禁 #6 会扫手写紫粉渐变；#2/#3 扫裸色/裸字体——但"假数据"机器拦不住，
> 只能靠你自己诚实。

## 动画决策树（财报解读版——主导动画怎么选）

每步的动画分三层，先分清你面对的是哪层：

| 层 | 是什么 | 规则 |
|---|---|---|
| **主导动画** | 这一步在"演"的那件事（数字递增/条生长/占比填满） | 每步一个；**内容驱动**；不同 step 的主导动作必须不一样 |
| **伴随动画** | 衬托主导的小动作（hero 标题进场等） | 别抢戏；一两个就够 |
| **氛围微动** | 背景级的持续微动（KenBurns/Breathe/粒子） | **按步声明豁免**（见下）；财报视频少用——数据是主角，背景别动 |

### 第 0 步：先读 Checkpoint 2 已确认的动画词汇

打开该章 `timing.json` 的 `animation` 键——**那里面是 Checkpoint 2 用户确认过的主导
动画词汇，必须实现**。已标步按词汇走（组件照词汇选、档位照第二步定）；**未标步**
才走下面的决策树。不要跳过这一步重新"自由发挥"——那会让用户确认的动画方向作废。

### 第一步：问内容——这一步在"演"什么数据？

| 内容意图（财报场景） | 组件（主导） | 备注 |
|---|---|---|
| 一个关键数字要砸出来（营收/利润/增速） | `HeroNumber` / `Counter` | 数字动画到位即停，别加花活 |
| 增长趋势（营收多年走势/季度） | `BarGrow` / `YearBarGroup` / `StepStairs` | 多根条逐根长；**注意**：`YearBarGroup` 的 tone 只有灰/绿两档（组件限），单点涨跌语义色（橙/绿）由 `DeltaText`/`NumberPill` 承载 |
| 占比结构（分部收入/成本构成） | `DonutMeter` | 环从 0 填到目标；多环可并列 |
| 同比/环比/竞对对比 | `SplitCompare` | 中线滑过；两侧各放一个 hero 数字 |
| 涨跌方向（单点定性） | `DeltaText` / `NumberPill` | **涨橙跌绿**，别用橙绿以外的语义色 |
| 报表明细（三张表的关键行） | `Table` + `StaggerRow` | 行逐行亮；只放关键行，不放整表 |
| 趋势线/曲线（收入/利润走向） | `EChart`（受控） | 图表本体 `animation:false`，动效由引擎入场给 |
| 传导链（"毛利率降→净利降"的逻辑链） | `PathDraw` / `StepSequence` | 节点依次点亮 + 连线自绘 |
| 结论/风险要强调 | `MarkerBlock` / `PostIt` | 墨底反白砸结论 |

### 第二步：选档位

三档：快档 / 中档 / 慢档（**数值见 LIBRARY 动画原语表**——本章不重复定义）。
缓动：进场 `--ease-out`、强调 `--ease-emph`。

**财报节奏规则**：**快档为主，数字到位即停**——观众要看的是数，不是动画秀。
`--dur-slow` 只留给大场面（如全年趋势线的自绘）；数字类组件默认 fast。

### 第三步：查三条硬约束

1. **不同 step 的主导动作必须不一样**——全章一种动画 = 重做（完工自检第 2 条）
2. **动画窗口 ≤ 步长**——门禁 #17 会报"动效超出人声"；动画比口播长时三选一：
   写更长口播 / 拆 step / 调档位
3. **氛围微动要声明**——Phase 3 静态版必须零动画；KenBurns/Breathe/粒子这类
   "t=0 即组合态、无入场态"的氛围微动，须在 `timing.json` 的
   `"ambient": {"<step>": "<note>"}` 逐帧声明豁免，否则门禁报 blocker

> 别靠加氛围微动补救"主导动作不够多样"——财报视频最忌讳背景抢数据的戏。

### 第 1 章 = 全片风格锚（硬节点）

**第 1 章强制主线程开发 + 验收（含动画观感）**，没有"骨架版"概念——必须做到用户能
直接验收。它是全片动画节奏的风格锚：后面的章节都参照它的档位节奏与语义色用法。

### 并行开发时的三条硬规则（模式 C 的 prompt 必须带）

1. 该章 outline 段（信息池 + step 列表）与 `CHAPTER-CRAFT.md` 路径
2. 该章 `timing.json` 的已确认动画词汇（第 0 步的那份）
3. 第 1 章代码作风格参考 + 三条红线（token 全走 var / 数据可溯 / 涨跌语义色）

## 框架已经搭好的部分（理解就好，不需重写）

- **舞台**：尺寸由档案定（16:9 → 1920×1080；3:4 → 1080×1440），外层 transform
  scale 缩到任何视口——**没有响应式断点**
- **安全框**（V1，数值见 LIBRARY 构图基础设施——本章不重复定义）：`?showcase=1&guides=1`
  有参考线；无头门禁 #20 会量真实文字越界
- **字幕层是框架级的**：文本强制来自 `narrations`，章节在结构上**无法**硬编码
  字幕（别去写，写了也进不了片）
- **推进**：音频驱动自动播放（`audio.ended` 且动画窗口结束 → 停留垫 → next）；
  无音频时退化估时。播放控制（播放/暂停/停止/导出）在框架，章节不碰
- **渲染**：成片 = 逐帧 seek 截图拼的，不是录屏——所以动画必须走组件
  （引擎注册表），手写 CSS animation 进不了 seek 运行时

## 代码层最小约束（每条红线 ↔ 对应门禁）

| 红线 | 门禁 | 后果 |
|---|---|---|
| 颜色禁硬编码（hex/rgb/命名色）——走 `var(--*)` token | #2 blocker | 换主题就破 |
| 字体家族禁硬编码——走 `var(--font-*)` | #3 blocker | 同上 |
| 动画时长禁裸值——走 `var(--dur-*)`；缓动走 `var(--ease-*)` | #4 blocker | seek 运行时读不到 |
| 禁 `setTimeout`/`setInterval`/`Math.random`/`Date.now`/`requestAnimationFrame` | #7 blocker | 渲染确定性被破坏 |
| 禁无限循环动画（infinite iterations） | #8 blocker | 渲染不出帧 |
| 动画必须走组件（引擎注册表）——禁手写 CSS animation/transition 驱动画面 | #16③ 动画逃逸（无头；"注册表覆盖断言"即 audit 的 unowned 判据） | 分镜/渲染抓不到你的动画 |
| 字号 ∈ 字阶集合（最小 `--t-label` 24px，最大 display 130px） | #5 warning | 视觉规则 V4 破 |
| 间距 ∈ `--space` 集合 | #5b warning | 同上 |
| 组件必须从组件库取（reacticle 受控组件），禁手写裸样式 | 章节层真实拦网 = #2/#3/#4（静态）+ #16③ 动画逃逸（无头）；#9 只管组件库自身 | 主题/门禁全失效 |
| 章节物理隔离：独立文件夹 + `.cdp-` 类前缀（前缀是**约定**，机器门禁只扫 components/ 目录，不扫章节 CSS） | 人审 | 互相污染 |
| **涨跌语义色**：涨=橙(accent-3)、跌=绿(accent-1)——数字/标签/条形全部遵循，禁橙绿以外的语义色 | #2（色值面）+ 人审 | A股语境下观众本能读色，用错色=信息错误 |
| **数据真实**：画面每个数字都能回 `article.md` 定位；编造数据 = 返工 | 人审（机器拦不住） | 金融内容的生死线 |

> 组件层"可用什么 token"看 `LIBRARY.md` 的 token 契约；每一列的报错原文与
> 修法看 `GATES.md` 对应编号。

## 完工自检（写完每章**强制**执行，不可跳过）

> ⚠️ **硬性流程**：实现完成 → 自检 → 修复 → 汇报。**禁止**"实现完成 → 直接汇报"。
> 执行方式（按能力降级）：优先独立 reviewer agent（传本章路径 + 本清单，逐项
> 核查+出结论）；其次 subagent；都没有就自己严格逐项。**直接拿原始结论汇报但
> 不修复 = 违规。**

写完一章 + 在浏览器点完一遍后逐项过：

- [ ] **每章至少 1~2 处"在演"的演示元素**（且来自组件库）——没有 = 回去补
- [ ] **不同 step 的主导动作不一样**——全章一种动画 = 重做
- [ ] 字号大（≥24px，hero 可到 130px）、留白舒服、配色舒服
- [ ] 清单/列表逐个揭示，**1 项 = 1 step**
- [ ] 画面信息比口播多（回 `article.md` 抽了细节挂上来）
- [ ] 无紫粉渐变/圆角彩色边框/emoji/**假 K 线/假大屏/深蓝金渐变**等指纹
- [ ] 缺的数据用 `<Figure>` 占位（注明数据来源），不是 fake；**主动告诉用户缺哪些**
- [ ] 无页眉页脚、无大片纯文字、无小字
- [ ] 颜色/字体/动画时长/缓动全部走 token；组件全部来自组件库
- [ ] **涨跌语义色正确**：涨=橙、跌=绿，全片一致；无橙绿混用
- [ ] **画面数字可溯**：每个数都能在 `article.md` 定位；单位/口径标在画面上
- [ ] 氛围微动（如有）已在 `timing.json` 的 `ambient` 逐帧声明
- [ ] 章节物理隔离：独立文件夹 + 类前缀，未跨章 import，未改共享文件
- [ ] **`npm run check:fast` 通过（0 blocker）**——不通过禁止汇报"做完了"；
      warning 逐条说明理由
- [ ] 每个 step 的动画窗口 ≤ 步长（#17 无"动效超出人声"提示）

任一未过 → 回去改。**不要**"先放着以后修"。
