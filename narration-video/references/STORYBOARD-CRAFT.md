# Phase 3 · 静态分镜作业手册（STORYBOARD-CRAFT）

Phase 3 的产物是拿给用户在 **Checkpoint 2** 确认的。所以它必须"像成片"，不是
"像代码"。本手册 = 怎么写静态终态版 + 怎么标注 + 怎么产出分镜页 + Checkpoint 2
怎么对。

---

## 一、这一步在做什么（Layout Contract）

**静态终态版先行**：每章写一个"每步的**终态构图**"版本，**禁一切动画**——
因为动画方向要在 Checkpoint 2 一次性跟你确认，而动画实现留给 Phase 4。

- 每步 = 这一步**讲完之后**画面应该停在哪（终态），不是"动画演到一半的样子"
- 用组件库里的**静态组件**拼终态（`HeroNumber`/`StatCard`/`Table`/`SplitCompare`/
  `MarkerBlock`/`DonutMeter` 停在满值……）；动画组件（`Counter`/`BarGrow`/reveal
  组/氛围组）**这一步不挂**——它们归 Phase 4，你现在只在标注里写"此步将用它们"
- **门禁会验**：`npm run storyboard` 跑零动画断言（引擎注册表 + WAAPI 之和 >0 即
  blocker）。氛围微动若要保留（KenBurns 等），必须在 `timing.json` 的 `ambient`
  逐帧声明豁免——**入场动画一律禁入静态版**，没有任何豁免

> **财报场景的终态**：每步终态 = 一个数据点的完整呈现（hero 数字 + 单位口径 +
> 感受锚点或对比元素）。观众在 Checkpoint 2 看分镜页时，应该像在翻"逐页财报"。

## 二、每帧的标注：`timing.json` 三键

每章可有一个 `src/chapters/<folder>/timing.json`（可选，缺了=全默认）：

```json
{
  "dwell":     { "3": 600 },
  "animation": { "3": "Counter + BarGrow" },
  "ambient":   { "0": "KenBurns 背景缓推（引擎测试脚手架）" }
}
```

| 键 | 是什么 | 财报场景的用法 |
|---|---|---|
| `dwell` | 该步**停留垫覆盖值**（ms；缺省 = 引擎默认 400ms）——停留垫三级：引擎 400 → 档案级（B站/小红书档均不覆盖）→ 本键逐帧 | 数据步留长一点（观众要看清数字）；转折步留短一点 |
| `animation` | 该帧的**主导动画词汇**（如 `Counter + BarGrow`）——Checkpoint 2 确认的就是它 | 写"词汇"不写参数：`BarGrow` 不写 `700ms ease-out` |
| `ambient` | **氛围声明**——声明步允许动画计数 >0（KenBurns/粒子等"t=0 即组合态"的微动），note 上分镜帧 | 财报视频少用；用了就声明 |

## 三、产出分镜页

> **先 `npm run dev`**——storyboard 不自动起服。

```bash
npm run storyboard                       # 逐帧截图 → storyboard/index.html + storyboard.json + shots/
npm run storyboard -- --verify-sequential   # 顺序推进 vs 独立 mount 逐字节一致（渲染模型前置门禁）
```

分镜页每帧显示：**静态终态图 + 口播文本 + 音频实测时长 + 停留垫（可调）+ 动画词汇
（未标注显示"未标注"）+ 氛围 note**。

- 音频实测时长来自 `public/audio-durations.json`（Phase 2 合成）；未合成时显示
  "未合成音频（Phase 2 后回正）"——分镜照样可出，但停留节奏是估时的
- **门禁**：帧数 === 总 step 数；零动画（氛围豁免外）

## 四、Checkpoint 2 怎么对

> ── **Checkpoint 2：静态构图 + 每帧停留节奏 + 动画方向，一次确认** ──

把 `storyboard/index.html` 交给用户（离线可开）。用户确认三件事：

1. **静态构图**：每帧画面是不是这一步该有的终态（数据对不对、构图顺不顺）
2. **停留节奏**：每帧停多久（dwell 可调——用户在分镜页上就能说"第 3 帧再停久点"）
3. **动画方向**：每帧的"主导动画词汇"认不认可（这是**定方向**，不是定实现）

**反馈分级**（收到意见后怎么走）：

| 用户要改的 | 走哪条路 |
|---|---|
| 构图 / 停留垫 | 直通 Phase 4 前的数据修改——改静态版 + `timing.json`，重截受影响帧 |
| 文本 / 切分 | 回 Phase 1 改 `script.md` → 重生成 narrations → 增量重合成（只重合成受影响段）→ 重截受影响帧 |
| 动画方向 | 改 `timing.json` 的 `animation` 词汇，重新确认——**不用重截**（静态帧没变） |

## 五、静态终态版怎么写（财报版要点）

**第 0 条（M6 新增——决定构图之前）：先选屏型。** 构图的正样只有 showcase 的
27 屏：按 LIBRARY.md「构图模板册」的映射表为每帧选一型（封面/数据墙/流程三步/
便签墙/对比屏/墨底结论/指标带/收尾屏），再按该型组件清单填数据。**排版铁律**：
每屏主角块 ≤1 + 辅助块 ≤3；4 卡 2×2 对角线同色；底色全铺；数据过密就拆帧
（回 Phase 1 改稿拆拍——不许单帧堆 2 个以上数据组）；第 1 步 = S1 封面排版。

1. **每步一个数据点**：终态 = 这个数据点讲完后的完整画面。口播念的是"营收 843 亿
   同比 +12.4%"，终态画面 = `HeroNumber` 843 + `DeltaText` "+12.4% 同比" + 一句
   感受锚点（"什么概念？……"）
2. **单位/口径上画面**：观众看分镜页第一眼就该看到"亿元""同比"——这同时是 Phase 4
   的完工作业项
3. **涨跌语义色**：涨橙跌绿，在终态版就定好——这是构图的组成部分
4. **静态组件的终态呈现**：`DonutMeter` 停在目标值、`SplitCompare` 两侧填满、
   `Table` 关键行全部可见——Phase 4 再把这些"终态"变成"动画到终态"
5. **画面补口播没念的细节**：口播只念 3 个数，终态画面可以把分部表挂全——这正是
   分镜页要让用户确认的"画面信息密度"

## 六、Phase 3 自检（强制）

- [ ] 静态版**零动画**（`npm run storyboard` 门禁通过；氛围微动已逐帧声明）
- [ ] 帧数 === 总 step 数（门禁自动验）
- [ ] 每帧终态 = 该步讲完后的完整画面，不是"演到一半"
- [ ] 每个数据点：数字 + 单位 + 口径在画面上；涨跌语义色正确
- [ ] 每帧的 `animation` 词汇已标（或明确决定"此步无主导动画"）
- [ ] 数据可溯（回 article 定位）；缺素材用 `<Figure>` 占位并列入素材清单
- [ ] `--verify-sequential` 通过（顺序推进 vs 独立 mount 逐字节一致）
